SLIDE 2: THE PROBLEM STATEMENT & REAL-WORLD CHALLENGE
--------------------------------------------------------------------------------
- Core Problem Statement:
  'My internet connection has stopped working. Help me fix it.'
- Key Industry Pain Points:
  1. Call Center Congestion: Average wait times of 15 to 30 minutes for ISP support.
  2. Rigid Scripted Chatbots: Traditional chatbots ask repetitive, generic questions
     without understanding what troubleshooting steps already failed.
  3. No Incident Memory: When users reconnect, they must repeat their entire story.
  4. Regional Outage Blindness: Standard bots force users to reset hardware even when
     the issue is a confirmed regional ISP backbone outage.
- Objective of NetCare AI:
  Build a fully automated, empathetic, 24/7 technical support agent that diagnoses faults,
  adapts dynamically based on user feedback, learns from previous resolved cases, and
  escalates to human technicians with formal tickets when necessary.

--------------------------------------------------------------------------------
SLIDE 3: SYSTEM ARCHITECTURE & THE 5 SPECIALIZED AGENTS (Unit IV)
--------------------------------------------------------------------------------
Rather than using a single monolithic prompt, NetCare AI implements 5 Role-Based Agents
collaborating in a structured pipeline:

1. COORDINATOR AGENT (The Central Orchestrator)
   - Serves as the primary point of contact for the customer.
   - Retrieves customer plan, billing status, and location from the database.
   - Searches past solved cases using Case-Based Reasoning (CBR).
   - Coordinates with Diagnosis and Troubleshooting agents to deliver a cohesive response.

2. DIAGNOSIS AGENT (Network Health Evaluator)
   - Runs simulated multi-layer diagnostics:
     * Fiber Optical Signal (ONT Status)
     * Router WAN Link / Cable Connection
     * Local IP Address Assignment (DHCP)
     * Gateway & DNS Ping
     * Regional ISP Backbone Health
   - Determines the underlying cause (hardware, Wi-Fi, DNS, or ISP outage).

3. TROUBLESHOOTING AGENT (Prescriptive Fixer)
   - Recommends actionable, progressive fixes (e.g., power cycling, cable check, Wi-Fi reset).
   - Dynamically calls Google Gemini GenAI to provide human-like, conversational explanations.

4. MONITORING AGENT (Feedback & Adaptation Engine)
   - Implements Unit III Feedback-Based Adaptation.
   - Evaluates user feedback (1-click buttons or typed chat replies).
   - Tracks failed attempts to prevent infinite loops.

5. ESCALATION AGENT (The Safety Net)
   - Intervenes when remote steps fail (after 3 tries) or when an ISP outage is detected.
   - Creates a formal Support Ticket (TKT-XXXX) with priority, reason, and attempted steps.

SLIDE 4: UNIT III -- FEEDBACK-BASED ADAPTATION CYCLE
--------------------------------------------------------------------------------
NetCare AI demonstrates an autonomous closed-loop adaptation cycle:

           [ ACT ] ------------> Recommends specific fix (e.g. Restart Router)
              |
              v
        [ OBSERVE ] ----------> Captures customer feedback ('Still not working')
              |
              v
        [ REFLECT ] ----------> Analyzes failure; eliminates the failed step
              |
              v
        [ ADJUST ] -----------> Selects next progressive action OR escalates

- Why This Matters:
  * Static bots repeat 'Restart your router'.
  * NetCare AI reflects on the failure and transitions to 'Check physical WAN cables',
    and eventually escalates if all remote attempts are exhausted.

--------------------------------------------------------------------------------
SLIDE 5: CASE-BASED REASONING & CONTINUOUS LEARNING
--------------------------------------------------------------------------------
- The Knowledge Base Memory Loop:
  1. Store: When an issue is successfully resolved, the session details are stored
     in the 'resolved_cases' table (Symptoms, Diagnosis, Successful Fix, Outcome).
  2. Retrieve: When a new customer describes an issue, the Coordinator Agent runs a
     similarity search over the case repository.
  3. Reuse: If a match is found, NetCare AI prioritizes the previously winning solution
     and displays a 'Past Case Retrieved' card to the user.
- Benefit: Accelerates time-to-resolution by up to 60%.

SLIDE 11: JURY Q&A CHEAT SHEET (TOP 5 QUESTIONS & ANSWERS)
--------------------------------------------------------------------------------
Q1: Why use 5 agents instead of one single prompt?
A1: Monolithic prompts are prone to hallucination, lose track of attempts, and fail to
    enforce business rules. Modular role-based agents separate diagnosis, execution,
    monitoring, and escalation with clear boundaries and auditable logs.

Q2: How does the system prevent infinite loops if the user keeps saying 'not working'?
A2: The Monitoring Agent enforces a strict MAX_ATTEMPTS threshold (set to 3). Once reached,
    it automatically halts troubleshooting and delegates to the Escalation Agent.

Q3: What happens if the internet goes down or the Gemini API quota is exceeded?
A3: The architecture includes an automatic multi-model fallback. If Gemini 3.5 Flash is
    unavailable, it cascades to Gemini 3.5 Flash Lite, and then to the built-in Offline
    Rule Engine, ensuring 100% uptime.

Q4: How does NetCare AI learn without retraining the AI model?
A4: Through Case-Based Reasoning (CBR). Resolved cases are indexed in SQLite with symptoms
    and winning actions. Subsequent sessions query this database to reuse proven solutions.

Q5: What is the tech stack and why?
A5: Python Flask backend for lightweight speed, SQLite for zero-config persistence,
    Google Gemini SDK for natural language reasoning, and Vanilla JS/CSS for a fast,
    dependency-free frontend.
